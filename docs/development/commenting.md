# 주석 작성 기준

주석은 코드 문법을 번역하는 설명이 아니라, 코드만으로 드러나지 않는 책임·정책·제약과 실패 결과를 보존한다.
모든 기존 로직은 이 기준을 충족하도록 정비하고, 새로 만들거나 수정한 로직은 같은 변경 안에서 주석까지 완성한다.

## 1. 클래스 주석

업무 로직이나 실행 흐름을 가진 클래스에는 다음 중 해당하는 내용을 설명한다.

- 클래스가 소유하는 하나의 책임
- 호출되는 맥락과 주요 호출자
- 입력에서 결과까지의 주요 처리 단계
- 신뢰 경계와 권한 전제
- 트랜잭션, 외부 시스템과 저장소의 관계
- 다른 클래스와 책임을 나눈 이유

단순 값 객체, 예외 타입과 이름만으로 책임이 충분히 드러나는 선언에는 형식적인 장문을 반복하지 않는다.

## 2. 메서드 주석

호출자가 구현을 읽지 않고도 계약을 이해할 수 있게 다음을 설명한다.

- 입력의 의미와 유효 범위
- 반환값과 특수 반환값의 의미
- 상태 변경, 저장, 이벤트·메트릭 기록 같은 부수 효과
- 발생 가능한 실패와 외부로 전달되는 결과
- 트랜잭션과 롤백 범위
- 호출 순서나 선행 조건

private 메서드도 이름만으로 숨은 계약이 드러나지 않으면 같은 원칙으로 설명한다.

## 3. 로직 내부 주석

다음 내용은 해당 코드 가까이에 구체적으로 남긴다.

- 조건 분기가 구분하는 업무 정책
- 검증, 조회, 외부 호출과 저장 순서의 이유
- 권한·보안·개인정보에 관한 판단
- 동시성, 멱등성, 재시도와 캐시 정책
- fail-open 또는 fail-closed 선택
- 별도 트랜잭션, 재조회, lock이나 unique constraint가 막는 경쟁 조건
- 예외 변환과 상태 코드 선택
- 메트릭 결과값과 고카디널리티 방지
- null, sentinel, 빈 컬렉션 등 특수 값으로 제어 흐름을 전달하는 이유
- 성능과 정확성 사이의 의도적인 절충

## 4. 좋은 주석

좋은 주석은 코드가 무엇을 하는지가 아니라 왜 그렇게 해야 하는지를 말한다.

~~~java
// 외부 검사 중 DB 연결을 점유하지 않도록 검사는 트랜잭션 밖에서 수행한다.
RiskVerdict verdict = riskChecker.verify(url);
~~~

~~~java
// 여기서 예외를 던지면 실패 이벤트도 롤백되므로 먼저 null을 반환해 기록을 커밋한다.
return null;
~~~

## 5. 피할 주석

다음 주석은 작성하지 않는다.

~~~java
// 사용자를 조회한다.
User user = userRepository.findById(id);
~~~

- 메서드와 변수 이름을 그대로 반복하는 설명
- 현재 코드와 무관한 과거 작업 일지
- 근거 없는 추측이나 언젠가 필요할 것이라는 설명
- 실제 동작과 검증하지 않은 보안·성능 주장
- 코드가 바뀌어도 확인할 수 없는 외부 파일이나 특정 구현을 영구 기준으로 삼는 설명

## 6. 유지 규칙

- 코드를 수정할 때 인접한 주석이 현재 동작과 일치하는지 함께 검토한다.
- 정책이나 실패 방식이 바뀌면 관련 클래스·메서드·인라인 주석을 같은 변경에서 갱신한다.
- 주석 정비 중 구조 문제를 발견해도 승인 없이 리팩터링하지 않고 별도 개선 후보로 보고한다.
- 작업 완료 전에 변경한 파일 전체를 다시 읽어 누락되거나 낡은 설명이 없는지 확인한다.
