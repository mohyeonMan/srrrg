# 간격·밀도 점검 (실측 기준)

캠페인 화면을 시작점으로 수직 리듬·정렬축·카드 패딩·표/필터 밀도를 실제 렌더링에서 측정했다.
"조금 넓어 보인다" 를 근거로 삼지 않고 픽셀값과 주변 관계로 판단했다.
측정은 Chrome 데스크톱 캡처(1064×947)와 `getBoundingClientRect` / `getComputedStyle` 을 함께 썼다.
좁은 폭은 CSSOM 에서 실제 배포된 `@media` 규칙을 꺼내 강제 적용해 측정했다.

---

## 1. 캠페인 헤더와 탭 사이 60px, 그중 40px 가 순수 공백

**측정값 (수정 전)**

| 구간 | 값 |
|---|---|
| 헤더 카드 하단 | y=366 |
| `#campaigns-message` (빈 요소) | y=386~406, height **20px**, `min-height: 20px` |
| 탭 바 상단 | y=426 |
| **헤더 → 탭 총 간격** | **60px** |

**원인**
`.form-message` 에 `min-height: 20px` 가 있다. 폼 안에서는 메시지가 나타날 때 제출 버튼이
밀리지 않게 자리를 예약하는 합당한 처리다. 그런데 `#campaigns-message` 는 화면 최상위에서
헤더 카드와 탭 사이에 놓인 **섹션 사이 상태 줄**이라, 비어 있어도 20px 를 차지하고
부모 `#campaigns-app` 의 `gap: 20px` 이 위아래로 한 번씩 더 붙어 60px 가 됐다.
사용자가 보는 것은 20px 짜리 투명한 띠와 40px 의 빈 공간이다.

같은 구조가 `#project-message`(프로젝트 화면)에도 있었다. 이쪽 부모는 grid 가 아니라
비용이 20px 로 작았지만 원인은 같다.

**수정**
버튼과 붙어 있지 않은 최상위 상태 줄만 비었을 때 흐름에서 뺀다.
폼 내부 메시지의 `min-height` 예약은 그대로 둔다 — 그쪽은 오클릭 위험이 실재한다.

```css
#projects-app > .form-message:empty,
#campaigns-app > .form-message:empty,
#project-settings-app > .form-message:empty,
#project-members-app > .form-message:empty { display: none; }
```

**검증** 헤더 → 탭 **60px → 20px**.
회귀 확인: JS 로 메시지를 넣으면 `display: block` 으로 다시 나타나고 간격이 60px 로 돌아가며,
비우면 다시 `none` + 20px 로 접힌다. 메시지 표시 기능은 손상되지 않았다.

## 2. 필터 아래 간격이 margin 과 gap 의 합으로 두 배

**측정값 (수정 전)** 필터 → 지표 격자 **40px**

**원인**
`.statistics-filter { margin-bottom: var(--space-5) }` 20px 와
부모 `.analytics-panel { gap: var(--space-5) }` 20px 가 더해졌다.
`/manage` 의 `.analytics-custom-period` 도 `margin-bottom: var(--space-4)` 16px + gap 20px = 36px 로
같은 패턴이었다.

**수정** 두 필터의 `margin-bottom` 삭제. 아래 간격은 부모 grid 의 gap 하나가 정한다.

**검증** 필터 → 지표 **40px → 20px** (캠페인·프로젝트·`/manage` 모두).

## 3. "적용" 버튼이 자기 줄 왼쪽 끝에 홀로 남음

**측정값 (수정 전)**
컨트롤 5개(기간 칩 + 시작일 + 종료일 + 집계 + 적용)가 한 줄에 들어가지 않아
적용만 다음 줄로 내려갔다. 그 위치가 `left: 326` — 필터 블록의 왼쪽 끝이고,
오른쪽으로 약 700px 가 비었다. 필터 행 높이는 118px 였다.

**판단**
이 폭(본문 약 600px)에서 컨트롤 5개는 물리적으로 한 줄에 들어가지 않는다.
줄바꿈 자체는 불가피하므로 없애려 하지 않았다. 문제는 버려진 것처럼 보이는 **위치**다.

**수정** `button[type="submit"] { margin-left: auto }`.
한 줄에 들어가면 오른쪽 끝에 붙고, 줄바꿈되면 그 줄의 오른쪽 끝에 놓여
필터 블록을 닫는 행동으로 읽힌다.

**제외한 대안**
- 필드 `min-width` 축소: 9.5rem → 8rem 으로 줄여도 합계가 여전히 폭을 넘고,
  날짜 입력은 `2026-07-14` + 달력 아이콘 때문에 약 130px 아래로 못 줄인다.
- grid 로 열을 고정: 이 폭에서 날짜 입력이 106px 로 눌려 값이 잘린다.

**검증** 적용 버튼 오른쪽 끝이 필터 블록 오른쪽 끝과 일치(`applyRightAligned: true`,
오차 2px 미만). `/manage` 는 폭이 넓어 같은 줄 오른쪽 끝에 정렬된다.

## 4. 카드 패딩이 세 갈래로 갈려 있었음

**측정값 (수정 전)**

| 대상 | 패딩 | 토큰 사용 |
|---|---|---|
| 캠페인 헤더 카드 | 28px | ✗ `clamp(20px,3vw,28px)` 직접 |
| 통계 제목 카드 | 28px | ✗ 같은 하드코딩 |
| 탭 바 | 28px | ✗ 같은 하드코딩 |
| 콘솔 패널 | 28px | ✗ 같은 하드코딩 |
| 프로젝트 설정 카드 | 28px | ✗ 같은 하드코딩 |
| `--panel-padding` 토큰 | **24px** | — |
| 지표 셀 | 16px | 의도된 압축 |

토큰이 24px 을 정해 두었는데 주요 카드 5곳이 28px 을 각자 적어 두고 있었다.
`--panel-padding` 을 쓰는 곳(`.create-tool`, `.decision-panel`, `.account-card` 등)과
어긋나 화면을 오갈 때 카드 내부 여백이 미묘하게 달랐다.

**수정** 하드코딩 5곳을 `var(--panel-padding)` 으로 교체.

**검증** `clamp(20px, 3vw, 28px)` 잔존 0곳. 캠페인 헤더 카드 높이 123px → **114px**,
패딩 28px → 23.4px(이 폭에서의 토큰 값).

**유지한 것** 지표 셀 16px(모바일 12px)은 그대로 뒀다.
6칸이 한 면에 들어가는 압축 격자라 카드 패딩과 같은 값을 쓰면 값이 들어갈 자리가 없다.
카드 종류에 따라 내부 패딩이 다른 것은 밀도 선택이고, 정렬은 **카드 경계**가 담당한다(6번 참조).

## 5. 탭 라벨이 본문 정렬축에서 16px 밀려 있었음

**측정값 (수정 전, `/manage`)**

| 요소 | left |
|---|---|
| 카드 경계 | 16 |
| 카드 패딩 | 23.4 |
| 제목 `훈삼링크1` | **41** |
| 단축 URL | **41** |
| 상태 배지 | **41** |
| 패널 제목 `상세 통계` | **41** |
| **첫 탭 라벨 `통계`** | **57** |

제목·URL·배지·패널 제목이 모두 x=41 축에 서 있는데 첫 탭 라벨만 57 에서 시작했다.
탭 바 패딩 24px 위에 탭 자체의 좌우 패딩 16px 이 더 붙은 결과다.

**1차 시도와 실패**
`:first-child { padding-left: 0 }` 만 주었더니 라벨이 축에 붙지 않았다.
버튼이 라벨을 **중앙 정렬**하고 `min-width: 112px` 이 있어서, 좌측 패딩을 없애도
라벨은 112px 박스 안에서 가운데(약 x=83)에 머물렀다.

또 이 과정에서 `.console-tab` 규칙을 잘못 쪼개 `color`·`background`·`border` 선언이
`:first-child` 쪽으로 넘어갔고, 두 번째 탭이 기본 버튼 테두리를 드러냈다.
**캡처로 발견**했다 — 정렬값 측정만으로는 드러나지 않는 종류의 오류였다.

**최종 수정**
탭에서 좌우 패딩을 없애고 라벨 사이를 `gap: var(--space-6)` 24px 로 벌렸다.
`min-width: 112px` → `0` 으로 라벨 폭을 그대로 쓴다.

**검증**
캠페인 화면에서 캠페인 제목 / 첫 탭 라벨 / 통계 제목이 모두 **x=351** 로 일치(`aligned: true`).
탭 타깃은 28×48, 61×48 — 폭 28px 로 WCAG 2.5.8 의 24px 최소를 넘고,
24px 간격으로 간격 예외도 만족한다.
부수 효과로 선택 밑줄이 라벨 폭에 맞아 무엇이 선택됐는지 더 정확히 가리킨다.

## 6. 정렬축은 카드 경계가 담당 — 수정하지 않음

내부 텍스트끼리 비교하면 통계 제목(x=351)과 지표 셀 텍스트(x=343)가 8px 어긋나 보였다.
이걸 정렬 버그로 볼지 판단하려고 **카드 경계**를 측정했다.

| 카드 | left | right |
|---|---|---|
| 캠페인 헤더 카드 | 326 | 1032 |
| 탭 바 | 326 | 1032 |
| 통계 제목 카드 | 326 | 1032 |
| 지표 격자 | 326 | 1032 |
| 추이 섹션 | 326 | 1032 |

**경계 5개가 전부 일치한다**(`edgesAligned: true`).
8px 차이는 카드 종류별 내부 패딩(제목 카드 24px, 섹션 20px, 지표 셀 16px)에서 나온 것이고,
서로 다른 카드의 *내부* 텍스트가 같은 축에 설 이유는 없다.
정렬의 기준은 카드 경계이며 그것은 어긋나 있지 않다. **수정하지 않는다.**

## 7. 통계 제목 카드와 본문 사이만 리듬이 끊김

**측정값 (수정 전)** 통계 제목 카드 → 필터 **0px**

`#statistics-app` 은 평범한 div 라 gap 이 없고, 제목 카드와 `.analytics-panel` 이
형제로 맞붙어 있었다. 본문 내부는 `.analytics-panel` 의 gap 으로 전부 20px 인데
제목 다음만 0px 이라 리듬이 한 번 끊겼다.

**수정** `#statistics-app { display: grid; gap: var(--space-5) }`

**검증 (수정 후 캠페인 화면 전체 리듬)**

| 구간 | 간격 |
|---|---|
| 캠페인 헤더 → 탭 바 | 20px |
| 탭 바 → 통계 제목 | 20px |
| 통계 제목 → 필터 | 20px |
| 필터 → 지표 격자 | 20px |
| 지표 격자 → 추이 섹션 | 20px |

`allTwenty: true`. 여섯 경계가 모두 20px 로 균일하다.

## 8. 상태 배지 좌측 마커가 라운딩에 걸려 괄호처럼 렌더

**측정값** `box-shadow: inset 3px 0 0` + `border-radius: 6px`.
캡처에서 "사용 가능" 배지 왼쪽에 곡선 조각이 생겨 여는 괄호처럼 보였다.

**판단**
이 배지는 상태를 **글자로 이미 말한다** — "사용 가능", "만료됨" 처럼 라벨 자체가 구분자다.
색은 보강이고 마커는 정보를 더하지 않는다. 색만으로 판단하게 두지 않는다는 조건은
라벨 텍스트가 이미 충족한다. 정보가 없는 장식이 렌더까지 지저분하므로 뺀다.

**수정** 상태색 배지의 inset 마커 삭제. 색조 배경 + 색 글자만 남김.

**검증** 캡처에서 곡선 조각 사라짐, 배지가 깔끔한 색조 pill 로 렌더.

## 서비스 전체 간격 원칙 (이번 측정에서 도출)

측정 결과 문제의 대부분이 **간격을 두 곳에서 정한 것**에서 나왔다.
`margin` + `gap`, `min-height` + `gap`, 하드코딩 패딩 + 토큰.
그래서 원칙은 "값을 늘리거나 줄이자" 가 아니라 "간격을 정하는 주체를 하나로 두자" 다.

**1. 간격은 부모가 정한다.**
형제 사이 간격은 부모의 `gap` 하나로만 만든다. 자식에 `margin-bottom` 을 두면
두 값이 더해져 의도한 간격의 두 배가 된다(2번에서 40px, 36px).
자식이 자기 아래 간격을 결정해야 하는 경우는 부모가 gap 을 쓸 수 없는 구조일 때뿐이다.

**2. 섹션 리듬은 `--space-5`(20px) 하나로 통일한다.**
카드와 카드, 제목 카드와 본문, 필터와 표 사이가 모두 20px 이다(7번 검증표).
같은 깊이의 형제는 같은 간격을 갖고, 다른 간격은 다른 위계를 뜻한다는 규칙이 성립해야 한다.

**3. 제목과 그 메타데이터는 `--space-2`(8px) 로 붙인다.**
한 덩어리로 읽히는 것끼리는 8px, 덩어리 사이는 20px. 이 두 값의 대비가 그룹을 만든다.

**4. 카드 내부 패딩은 세 단계만 쓴다.**
`--panel-padding`(24px) 주요 카드 / `--compact-panel-padding`(18px) 보조 카드 /
압축 격자 셀 16px. 값을 직접 적지 않는다. 카드 종류에 따라 내부 패딩이 다른 것은 정상이다.

**5. 정렬의 기준은 카드 경계다.**
서로 다른 카드의 내부 텍스트를 같은 축에 세우려 하지 않는다(6번).
다만 **같은 카드 안에서는** 제목·본문·탭 라벨이 한 축에 서야 한다(5번).

**6. 비어 있는 요소는 흐름에서 빠진다 — 단, 버튼 옆은 예외.**
섹션 사이 상태 줄은 비었을 때 `display: none`. 폼 내부 메시지는 `min-height` 를 유지해
제출 버튼이 밀리지 않게 한다. 오클릭 위험이 있는 자리에서는 예약이 공백보다 낫다.

**7. 줄바꿈이 불가피하면 위치로 의도를 보인다.**
컨트롤이 한 줄에 안 들어갈 때 억지로 줄이지 않는다. 대신 액션을 오른쪽 끝에 붙여
버려진 것이 아니라 블록을 닫는 것으로 읽히게 한다(3번).

## 반응형·키보드 검증

**좁은 폭 (강제 ≤1023/767/720/640/520/380px 규칙, 규칙 84개 적용)**

| 항목 | 결과 |
|---|---|
| 캠페인 헤더 → 탭 | 20px |
| 탭 → 통계 제목 | 20px |
| 필터 → 지표 | 20px |
| 지표 격자 열 수 | 1열 |
| 지표 셀 패딩 | 16px → **12px** (밀도 적응) |
| 탭 4개 | `nowrap`, 24px gap, 넘침 없음 |
| 문서 가로 오버플로 | 없음 |

접힌 상태에서도 20px 리듬이 유지되고, 지표 셀만 12px 로 조여 화면 폭을 값에 양보한다.

**키보드**
캠페인 탭에서 오른쪽 방향키 → `링크 목록` 으로 포커스 이동 + 패널 전환,
왼쪽 방향키 → `개요` 복귀. `tabIndexes: [-1, 0, -1, -1]` 로 roving tabindex 유지.
탭 패딩을 없앤 뒤에도 포커스 링과 방향키 동작에 변화 없음.

**콘솔** 캠페인·프로젝트·`/manage` 전부 오류 0.

## 부수적으로 확인해 유지한 것

**캠페인 설명이 짧을 때 헤더 카드가 커 보이는 문제** — 테스트 데이터의 설명이 "야르" 2글자라
카드가 비어 보인다. 패딩을 토큰으로 내려 123px → 114px 가 됐고 그 이상 줄이지 않았다.
설명이 한두 줄인 정상 데이터에서는 비율이 맞고, 짧은 데이터에 맞춰 패딩을 더 줄이면
설명이 길 때 답답해진다.

**`/manage` 로딩 상태** — 캡처 중 세션 만료(401)로 "링크 정보와 권한을 확인하고 있습니다."
상태가 잡혔다. 로딩 문구와 카드가 정상 동작하는 것을 확인했고 디자인 문제는 아니었다.

**미이동 지표의 보조 설명 "전체 진입 - 전체 이동"** — 수식처럼 읽히지만 이 지표가
어떻게 계산되는지 알려주는 정보다. 문구 개선은 이번 간격 점검 범위를 벗어나 남겼다.

## 남은 한계

**좁은 폭 광학 확인** — Chrome 창 리사이즈가 화면 경계 제약으로 실패하고
인앱 브라우저는 세션이 없어 워크스페이스를 좁은 폭으로 캡처할 수 없다.
좁은 폭 수치(간격·열 수·넘침)는 강제 규칙으로 검증했지만 광학 균형은 사람 눈이 필요하다.

**데이터 규모** 캠페인 2개·링크 1개 기준이다. 표 밀도와 지표 강조는
행이 수십 개로 늘었을 때 다시 봐야 한다.
