# srrrg UIUX v2 - 제품 전략

## 1. 문서 목적

이 문서는 srrrg 웹 UI를 고급 스타트업 제품 수준으로 정리하기 위한 제품 관점의 기준을 정의한다.

v2에서 유지할 것:

- `srrrg`의 푸른색 메인 컬러
- 밝고 깨끗한 SaaS 도구형 인상
- `신뢰할 수 있는 링크인가요?`처럼 사용자를 겁주지 않고 안내하는 친절한 보안 문구
- 비회원 기반으로 빠르게 단축 URL을 만들고 관리하는 흐름
- 원본 URL 확인, secret key, 만료 시각, 클릭/이동 통계라는 제품의 핵심 신뢰 요소

v2에서 개선할 것:

- 첫 화면의 우선순위
- 생성 결과 표시 방식
- 만료 선택 UX
- 링크 관리 UX
- 링크 확인 화면의 선택권
- 접근성 완성도

## 2. 제품 정의

### 2.1 한 줄 정의

```text
srrrg는 긴 링크를 짧게 만들고, 낯선 링크는 이동 전 원본 주소를 확인하게 해주는 가벼운 신뢰형 단축 URL 도구다.
```

### 2.2 제품 인상

srrrg는 과장된 보안 제품처럼 보여서는 안 된다. 사용자가 매번 긴장하게 만드는 빨간 경고 UI보다, 차분하고 친절한 확인 UI가 맞다.

목표 인상:

- 빠르다
- 가볍다
- 신뢰할 수 있다
- 설명이 과하지 않다
- 중요한 순간에는 정확하게 멈춰 세운다

피해야 할 인상:

- 랜딩 페이지처럼 말만 많고 도구가 늦게 나오는 화면
- 보안 경고가 과도해서 사용자를 겁주는 화면
- 개발자 API 문서가 일반 사용자 행동보다 앞서는 화면
- secret key를 평범한 결과값처럼 가볍게 다루는 화면
- 카드, shadow, gradient가 많아 장난감처럼 보이는 화면

## 3. 핵심 사용자

| 사용자 | 목표 | 불안 요소 | UI가 해결해야 할 것 |
|---|---|---|---|
| 일반 사용자 | 긴 URL을 빠르게 줄인다 | 복잡한 설정, 계정 생성 | 입력 즉시 생성되는 명확한 폼 |
| 링크 생성자 | 나중에 URL과 만료를 관리한다 | secret key 분실, 관리 방법 모름 | 생성 직후 secret key 보관 행동 유도 |
| 단축 링크 방문자 | 링크가 어디로 가는지 확인한다 | 피싱, 이상한 도메인, 자동 이동 | 원본 도메인과 전체 URL을 이해하기 쉽게 표시 |
| 개발자/API 사용자 | API 문서를 확인한다 | 웹 UI와 API 사용 경로 혼동 | API 문서는 보조 경로로 제공 |

## 4. v2 핵심 UX 변경 방향

### 4.1 첫 화면의 주인공을 URL 생성 폼으로 바꾼다

현재 홈은 히어로 문구와 API 문서 링크가 강하다. v2에서는 사용자의 1차 목표인 `URL 입력 후 단축 링크 생성`이 첫 시선에 들어와야 한다.

변경 원칙:

- 첫 화면에서 가장 큰 interactive element는 URL 입력 폼이다.
- primary CTA는 항상 `단축 URL 만들기`다.
- `API 문서 보기`, `OpenAPI JSON`은 보조 링크로 낮춘다.
- 히어로 문구는 폼의 이해를 돕는 정도로 짧게 둔다.
- 사용자가 스크롤하지 않아도 URL 생성 시작이 가능해야 한다.

### 4.2 생성 결과는 모달보다 인라인 결과를 우선한다

단축 URL 생성은 반복 작업이다. 생성 성공마다 모달을 띄우면 사용 흐름이 끊긴다.

v2 권장:

- 생성 성공 결과는 생성 폼 아래에 인라인 패널로 표시한다.
- 단축 URL과 secret key는 각각 복사 버튼을 붙인다.
- secret key는 `생성 직후 한 번만 확인 가능`하다는 안내를 결과 영역 안에서 강하게 표시한다.
- 오류, 삭제 확인, 위험한 작업에는 모달을 사용할 수 있다.

### 4.3 만료 설정은 빠른 선택 버튼으로 노출한다

만료 설정은 보안과 관리성에 영향을 주는 중요한 선택이다. 작은 select 안에 숨기면 사용자가 기본값을 이해하기 어렵다.

v2 권장:

```text
만료
[없음] [1시간] [하루] [1개월] [1년] [직접 입력]
```

직접 입력 선택 시에만 `datetime-local` 입력을 노출한다.

### 4.4 링크 관리는 생성 흐름보다 한 단계 낮춘다

대부분의 첫 방문자는 링크를 만들고 싶어 한다. 링크 관리는 생성 이후나 재방문 사용자에게 필요하다.

v2 권장:

- 홈 첫 화면은 생성 중심으로 구성한다.
- `내 링크 관리`는 secondary action 또는 별도 관리 패널로 제공한다.
- 관리 조회 성공 후에는 관리 작업을 집중해서 할 수 있는 패널 또는 모달을 연다.
- secret key는 브라우저 저장소에 저장하지 않는다.

### 4.5 확인 화면은 이동과 돌아가기를 모두 제공한다

`신뢰할 수 있는 링크인가요?` 화면은 사용자를 막기 위한 화면이 아니라, 사용자가 정보에 근거해 선택하게 하는 화면이다.

v2 권장:

- primary: `원본 URL로 이동`
- secondary: `돌아가기`
- 원본 도메인을 URL 전체보다 더 먼저 보여준다.
- 전체 URL은 접어서 볼 수 있게 하되, summary만으로도 도메인 판단이 가능해야 한다.

```text

│  ┌───────────────────────────────────────┐  │

│  │ 만료 [없음][1시간][하루][1개월][...]   │  │
│  │ [단축 URL 만들기]                     │  │
│  └───────────────────────────────────────┘  │
│                                             │
│  생성 결과 영역                            │
│                                             │
│  신뢰 기능 3개                             │
│                                             │
│  내 링크 관리                              │
│                                             │
│  API 문서 보기 · OpenAPI JSON              │
│                                             │
└─────────────────────────────────────────────┘
```

첫 viewport에서 반드시 보여야 하는 것:

- `srrrg` 브랜드
- 제품의 한 문장 가치
- URL 입력 필드
- `단축 URL 만들기` 버튼
- 만료 기본값이 `없음`임을 알 수 있는 UI

첫 viewport에서 강하지 않아도 되는 것:

- API 문서 링크
- 상세 기능 설명 카드
- 링크 관리 전체 폼
- 상세 통계

## 6. 디자인 원칙

### 6.1 우선순위

모든 화면은 아래 우선순위를 따른다.

1. 사용자가 지금 해야 할 행동
2. 사용자가 판단해야 할 정보
3. 행동 이후 보관해야 할 정보
4. 보조 설명
5. 개발자/API 보조 링크

홈에서는 `URL 입력`이 1순위다.

확인 화면에서는 `원본 도메인 확인`이 1순위다.

관리 화면에서는 `현재 링크 상태와 수정 가능 항목`이 1순위다.

### 6.2 신뢰 표현

신뢰는 자물쇠 아이콘이나 경고색으로 과시하지 않는다. 아래 요소로 만든다.

- 정확한 도메인 표시
- secret key의 일회성 안내
- 만료 여부와 생성/수정 시각 표시
- 클릭 수와 실제 이동 수를 구분해 표시
- 자동 이동되지 않는 링크는 이동 전 원본 주소 확인

### 6.3 밀도

srrrg는 단일 목적 도구이므로 화면 밀도를 적당히 높여도 된다.

- 히어로 문구는 짧게
- 입력과 결과는 가깝게
- 기능 카드 설명은 한 줄에서 두 줄 이내
- 보안 안내는 필요한 순간에만 노출
- 동일 설명을 여러 위치에 반복하지 않음

## 7. 콘텐츠 톤

srrrg의 말투는 다음과 같다.

- 짧다
- 친절하다
- 기술적으로 정확하다
- 겁주지 않는다
- 사용자의 행동을 분명히 안내한다

주요 용어:

| 사용 | 비고 |
|---|---|
| `단축 URL` | 핵심 제품 용어 |
| `원본 URL` | 이동 대상 |
| `secret key` | 영문 소문자 유지 |
| `만료 시각` | 날짜보다 정확한 표현 |
| `진입 수` | 단축 URL 접근 횟수 |
| `실제 이동 수` | 원본 URL redirect 횟수 |

피할 표현:

- `위험합니다`
- `악성 링크일 수 있습니다`
- `절대 이동하지 마세요`
- `보안상 차단되었습니다`

정책적으로 확정된 악성 판정이 아닌 이상 과장하지 않는다.
