# srrrg UIUX v3 - 제품 전략

## 1. 문서 목적과 범위

v2는 **비회원이 홈에서 단축 URL 하나를 만들고 관리하는 흐름**(`index.html`, `management.html`, `redirect-error.html`)을 다뤘고, 이미 코드에 반영되어 있다.

v3는 그 이후 확장된 **로그인 기반 팀 워크스페이스 전체**를 다룬다.

```text
로그인 (login.html)
프로젝트 (projects.html)
캠페인 (campaigns.html)
통계 (statistics.html)
초대 (invitation.html)
```

이 화면들은 기능은 모두 구현되어 있지만, 화면 하나에 만들기·목록·설정·멤버·삭제가 우선순위 없이 위에서 아래로 쌓여있는 **개발/테스트 수준 UI**다. v3는 이를 실제 팀이 매일 쓰는 SaaS 대시보드 수준으로 재설계한다.

v3에서 유지하는 것 (v2 계승):

- 브랜드 블루 토큰(`--color-brand` 계열), 배경 gradient, 타이포 스케일, 버튼·인풋·뱃지 스타일 등 v2 비주얼 시스템 전체
- 콘텐츠 톤(짧고 친절하고 겁주지 않음)과 기존 용어(단축 URL, 원본 URL, secret key, 만료 시각, 진입 수, 실제 이동 수)
- 비회원 홈(`/`)의 UX와 레이아웃은 변경하지 않는다. 로그인 워크스페이스는 별도 셸을 쓰는 완전히 다른 레이아웃이다.
- soft delete, 변경 즉시 반영 등 이미 코드로 확정된 정책

v3에서 새로 정의하는 것:

- 로그인 후 진입하는 **워크스페이스 셸**(좌측 사이드바 + 상단 바)
- 프로젝트/캠페인/UTM 템플릿/통계/멤버/설정을 하나의 페이지에서 분리해 **각자의 화면**으로 승격
- 데이터 테이블, 드로어(slide-over), 탭, 카드형 통계 등 대시보드 전용 컴포넌트
- Bitly류 링크 관리 제품의 탐색·필터·생성 패턴을 참고한 워크플로

## 2. 제품 정의 (업데이트)

```text
srrrg는 비회원도 즉시 쓸 수 있는 단축 URL 도구이자, 팀이 캠페인 단위로 UTM 링크를 대량 발행하고 채널별 성과를 추적하는 마케팅 링크 운영 플랫폼이다.
```

제품은 이제 두 층위로 나뉜다. 톤과 브랜드는 공유하지만 레이아웃 셸은 다르다.

| 층위 | 사용자 | 진입점 | 상태 |
|---|---|---|---|
| 단일 도구 | 비회원, 1회성 사용자 | `/` | v2에서 정리됨, 변경 없음 |
| 팀 워크스페이스 | 로그인한 팀, 반복 사용자 | `/login` → 프로젝트 | v3 재설계 대상 |

두 층위 사이의 다리는 명확해야 한다: 홈에서 만든 비회원 링크를 로그인 후 "기존 익명 링크 편입"으로 프로젝트에 옮길 수 있는 기능은 이미 있다(`projects.html`의 `import-section`). v3에서도 이 다리는 유지하되, 위계를 낮춰 프로젝트 설정 하위로 정리한다(4장 참고).

## 3. 핵심 사용자

| 사용자 | 목표 | 불안 요소 | UI가 해결해야 할 것 |
|---|---|---|---|
| 워크스페이스 오너 | 팀을 세팅하고 서브도메인·멤버를 관리한다 | 실수로 도메인을 잘못 바꾸거나 멤버 권한을 잘못 준다 | 설정을 독립 화면으로 분리, 위험한 작업에 명확한 확인 |
| 캠페인 매니저 (핵심 사용자) | 캠페인을 만들고 UTM 템플릿을 설계해 채널별 링크를 대량 발행한다 | 어느 화면에 뭐가 있는지 못 찾는다, CSV 임포트 상태를 놓친다 | 캠페인 상세를 탭으로 분리, 임포트 진행 상태를 항상 보이게 |
| 퍼포먼스 마케터 | 개별 채널에 배포할 링크를 빠르게 만들고 클릭을 확인한다 | 이 링크가 어느 캠페인 소속인지, UTM이 뭐가 적용됐는지 헷갈린다 | 링크 목록에서 프로젝트/캠페인 전체를 가로질러 검색·필터 |
| 조회 전용 이해관계자 (VIEWER) | 성과만 확인한다, 편집하지 않는다 | 실수로 뭔가 바꿀까봐 조심스럽다 | 편집 UI를 아예 숨기거나 비활성화, 통계 화면 진입을 쉽게 |
| 개발자/API 사용자 | 배치 생성·자동화를 API로 연결한다 | 웹 UI 문서와 API 문서가 섞여 헷갈린다 | API Key 발급은 설정 화면 안에, API 문서는 별도 링크로 유지 |

## 4. 현재 상태 진단 (As-Is)

실제 템플릿(`projects.html`, `campaigns.html`, `statistics.html`)을 검토해 확인한 문제:

1. **프로젝트 화면이 모든 것의 서랍이다.** 사이드바에 프로젝트 목록, 메인에 링크 생성 폼 → 최근 링크 → 캠페인 목록 → `<details>` 아코디언(프로젝트 설정 + 서브도메인 + 멤버/초대 + 기존 링크 편입)이 한 페이지에 순서대로 쌓여있다. 캠페인이 5개, 링크가 50개만 되어도 스크롤이 매우 길어진다.
2. **캠페인 화면은 select 하나로 캠페인을 전환하고, 그 아래 목적지 → UTM 템플릿 → 기본값 → 링크 생성 → 링크 테이블 → CSV 임포트 → 내보내기 → 삭제가 전부 세로로 나열된다.** 우선순위가 없어 "지금 이 캠페인의 링크 몇 개가 어떻게 도는지" 보다 "폼이 몇 개 있는지"가 먼저 보인다.
3. **UTM 템플릿이 캠페인 화면에 종속되어 있다.** 템플릿은 프로젝트 전체에서 재사용되는 자산인데, 특정 캠페인을 열어야만 만들고 편집할 수 있다.
4. **통계 진입점이 세 곳으로 흩어져 있다** — 링크별 통계(`management.html` 통계 탭), 캠페인 통계 링크(`campaigns.html`), 프로젝트/워크스페이스 통계(`statistics.html`). 각 계층의 관계(링크 < 캠페인 < 프로젝트)가 화면 구조로 드러나지 않는다.
5. **멤버·초대·프로젝트 설정·기존 링크 편입이 모두 `<details>` 아코디언 하나에 들어있다.** 위험한 작업(프로젝트 삭제, 서브도메인 반납)과 일상 작업(초대 보내기)이 같은 위계로 보인다.
6. **워크스페이스 개요 화면이 없다.** 로그인해서 프로젝트를 선택하면 바로 "링크 생성 폼"이 나오고, 오늘 무슨 일이 있었는지(신규 클릭, 만료 임박 캠페인 등) 요약하는 화면이 없다.
7. **전역 링크 검색이 없다.** 특정 링크를 찾으려면 그 링크가 속한 프로젝트/캠페인을 먼저 찾아 들어가야 한다.

## 5. v3 핵심 방향

### 5.1 사이드바 기반 워크스페이스 셸

로그인 후 화면은 좌측 고정 사이드바 + 상단 바 + 메인 콘텐츠로 통일한다. 사이드바는 워크스페이스(프로젝트) 전환과 최상위 내비게이션(개요/링크/캠페인/UTM 템플릿/통계/멤버/설정)을 담당한다. 자세한 구조는 [02_information_architecture.md](02_information_architecture.md) 참고.

### 5.2 프로젝트는 "서랍"이 아니라 "개요"다

프로젝트 진입 시 첫 화면은 요약(핵심 지표, 최근 활동, 만료 임박 항목)만 보여준다. 링크 생성·캠페인 관리·멤버 관리는 각자의 화면으로 이동해서 한다.

### 5.3 캠페인은 탭이 있는 상세 페이지로 승격

캠페인 하나는 목록에서 카드/행으로 보이고, 클릭하면 개요/링크/UTM 설정/통계 4개 탭이 있는 상세 페이지로 들어간다.

### 5.4 UTM 템플릿은 프로젝트 레벨 자산으로 독립

캠페인 화면에서 벗어나 프로젝트 사이드바에 `UTM 템플릿` 메뉴로 승격한다. 템플릿을 먼저 만들고, 캠페인에서는 "이미 있는 템플릿을 고르는" 흐름으로 바뀐다.

### 5.5 링크는 캠페인에 갇히지 않는다

프로젝트 전체 링크를 가로질러 검색·필터(캠페인별, 상태별, 기간별)할 수 있는 전역 링크 테이블을 둔다. 캠페인 상세의 링크 탭은 이 테이블에 캠페인 필터가 고정된 뷰다.

### 5.6 통계는 계층을 화면 구조로 드러낸다

링크 상세 드로어의 미니 통계 → 캠페인 상세의 통계 탭 → 프로젝트 통계 화면(캠페인 간 비교 포함) 순서로, 위로 갈수록 더 넓은 범위를 본다는 게 내비게이션만 봐도 이해되게 한다.

### 5.7 멤버·초대·설정·링크 편입은 독립 화면으로

`<details>` 아코디언을 없애고 `멤버`, `설정` 두 개의 사이드바 메뉴로 분리한다. 위험한 작업(삭제류)은 설정 화면 안에서도 별도 섹션(danger zone)으로 시각적으로 분리한다.

## 6. Bitly 벤치마크에서 가져올 것 / 가져오지 않을 것

참고 지시에 따라 Bitly류 링크 관리 대시보드의 패턴을 참고하되, srrrg의 "가볍고 겁주지 않는" 톤(v2 원칙)은 그대로 유지한다.

가져오는 것:

- 좌측 고정 nav + 상단에 통합 검색과 `Create` 계열 primary 버튼
- 링크를 리스트/테이블 중심으로 다루고, 상세는 모달이 아니라 옆에서 열리는 드로어로 확인
- 캠페인을 링크의 그룹핑 단위로 다루는 구조 (태그에 가까운 개념)
- 통계를 카드형 핵심 지표 + 추이 차트 + 분해표(breakdown) 조합으로 구성

가져오지 않는 것:

- 브랜드 킷, 커스텀 QR 코드 등 srrrg 범위 밖 기능
- 유료 플랜 게이팅을 흉내낸 잠금 아이콘, 업그레이드 유도 배너
- 마케팅 색이 짙은 무거운 랜딩형 첫 화면 — 워크스페이스 진입 후에는 바로 데이터가 보여야 한다

## 7. 정보 우선순위 원칙

모든 로그인 후 화면은 아래 우선순위를 따른다 (v2 6.1의 워크스페이스 버전).

1. 지금 사용자가 확인하려는 상태(이 캠페인이 잘 도는가, 이 링크가 몇 번 클릭됐는가)
2. 지금 사용자가 하려는 행동(링크 만들기, 멤버 초대하기)
3. 그 행동에 필요한 부가 정보(UTM 기본값, 만료 옵션)
4. 위험하거나 자주 쓰지 않는 설정
5. 다른 워크스페이스/화면으로의 이동

화면별 1순위:

| 화면 | 1순위 |
|---|---|
| 프로젝트 개요 | 오늘의 핵심 지표와 눈에 띄어야 할 이상 신호(만료 임박, 임포트 실패) |
| 링크 목록 | 검색/필터로 원하는 링크를 찾는 것 |
| 캠페인 목록 | 캠페인 상태(활성/보관)와 최근 활동 |
| 캠페인 상세 | 지금 보고 있는 캠페인이 무엇을 하고 있는지(목적지, 링크 수, 최근 클릭) |
| UTM 템플릿 | 어떤 템플릿이 몇 개 캠페인에서 쓰이는지 |
| 통계 | 선택한 기간의 핵심 지표와 추이 |
| 멤버 | 누가 무슨 권한으로 들어와 있는지 |
| 설정 | 현재 값과, 위험한 작업은 명확히 구분된 위치 |

## 8. 콘텐츠 톤 확장 (신규 용어)

v2의 용어 표(2.7절 콘텐츠 톤)를 아래처럼 확장한다.

| 용어 | 비고 |
|---|---|
| `워크스페이스` | 화면 표기에서는 되도록 `프로젝트`를 우선 사용하고, 여러 프로젝트를 아우르는 셸 개념을 설명할 때만 `워크스페이스` 사용 |
| `캠페인` | 유지 |
| `보관됨` | 삭제(soft delete)된 캠페인의 화면 표기. `삭제됨`이라는 단어는 되돌릴 수 없다는 인상을 주므로 캠페인에는 쓰지 않는다 |
| `UTM 템플릿` | 유지 |
| `멤버` / `초대` | 유지 |
| `OWNER` / `EDITOR` / `VIEWER` | 화면에는 영문 role을 그대로 노출하지 않고 `소유자`, `편집 가능`, `조회 전용`으로 표기 (기존 invitation.html 표기 방식 유지) |
| `대기 중` | 아직 수락되지 않은 초대 상태 |

피할 표현(v2 계승):

- `위험합니다`, `절대 이동하지 마세요` 등 과장된 경고
- 캠페인/프로젝트 삭제에 `영구 삭제`라는 표현은 실제로 soft delete인 캠페인에는 쓰지 않는다. 하드 삭제가 실제로 일어나는 프로젝트 삭제에만 명확히 `삭제 후 복구할 수 없습니다`라고 안내한다.
