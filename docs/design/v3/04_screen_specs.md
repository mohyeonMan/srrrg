# srrrg UIUX v3 - 화면 명세

전체 IA는 [02_information_architecture.md](02_information_architecture.md), 컴포넌트는 [03_visual_system.md](03_visual_system.md) 참고. 여기서는 화면별 목적·레이아웃·상태·카피를 정의한다.

## 1. 로그인 (`/login`)

### 1.1 변경 범위

현재 구현이 이미 단순하고 톤이 v2와 일관적이다(카드 하나, OAuth 3개, 에러/링크 안내 문구). 큰 구조 변경은 필요 없고 다음만 다듬는다.

- 카드 폭을 `420px`로 제한(현재 CSS 미확인이나 로그인 카드가 너무 넓으면 OAuth 버튼이 늘어져 어색해 보인다).
- OAuth 버튼에 각 provider 아이콘(Google/Kakao/GitHub 공식 마크)을 추가해 스캔 속도를 높인다. 텍스트만 있는 현재 상태(`Google로 계속`)는 나쁘지 않지만 아이콘이 있으면 인지 속도가 빨라진다.
- `param.link_required`, `param.error` 메시지는 현재도 적절한 톤이므로 문구 변경 없음.

### 1.2 레이아웃

```text
┌───────────────────────────┐
│        srrrg 로고          │
│      계정 로그인            │
│  srrrg에 로그인             │
│  사용할 계정을 선택하세요... │
│                            │
│  [G  Google로 계속]        │
│  [K  Kakao로 계속]         │
│  [Gh GitHub로 계속]        │
└───────────────────────────┘
```

## 2. 워크스페이스 진입 (`/projects`)

프로젝트 id 없이 진입했을 때의 분기 처리.

| 상황 | 동작 |
|---|---|
| 최근 방문한 프로젝트가 있음 | 그 프로젝트의 개요(`/projects/{id}`)로 즉시 이동 |
| 소속된 프로젝트가 있지만 방문 기록 없음(예: 다른 브라우저) | 목록에서 첫 번째 프로젝트로 이동 |
| 소속된 프로젝트가 하나도 없음 | 온보딩 화면: "첫 프로젝트를 만들어보세요" + 생성 폼 |

온보딩 화면은 사이드바 없이(아직 프로젝트가 없으므로 사이드바에 넣을 메뉴가 없다) 중앙 정렬된 단일 카드로 보여준다. 카피:

```text
첫 프로젝트를 만들어보세요
프로젝트는 팀이 함께 쓰는 단축 링크와 캠페인의 단위입니다.

[프로젝트 이름                    ]
[프로젝트 만들기]
```

## 3. 프로젝트 개요 (`/projects/{id}`)

### 3.1 목적

로그인 후 매일 처음 보는 화면. "지금 이 프로젝트에 신경 쓸 일이 있는가"에 답한다.

### 3.2 레이아웃

```text
┌──────────────────────────────────────────────────────┐
│ 여름 마케팅팀                                          │
│ srrrg.link/go 또는 summer.srrrg.link                   │
├──────────────────────────────────────────────────────┤
│ ┌──────────┐ ┌──────────┐ ┌──────────┐                │
│ │활성 링크  │ │활성 캠페인│ │최근 7일   │                │
│ │  128     │ │   6      │ │클릭 4,301 │                │
│ └──────────┘ └──────────┘ └──────────┘                │
│                                                        │
│ 눈에 띄는 항목                                          │
│ ⚠ CSV 임포트 1건 일부 실패 (12행)        [자세히 보기]  │
│ ⏱ "여름 세일" 캠페인 링크 3개 24시간 내 만료             │
│                                                        │
│ 최근 생성된 링크                          [전체 보기]   │
│ aB3x9Q → example.com/summer-sale     2026-08-10        │
│ ...                                                    │
│                                                        │
│ [+ 링크 만들기]   [+ 캠페인 만들기]                     │
└──────────────────────────────────────────────────────┘
```

### 3.3 "눈에 띄는 항목" 섹션 규칙

- 최대 3개까지만 노출. 우선순위: 실패/오류 > 만료 임박 > 정보성 안내.
- 항목이 하나도 없으면 섹션 자체를 렌더링하지 않는다(v2 "empty는 렌더링하지 않는다" 원칙 계승).
- 이 섹션은 알림센터가 아니다. 과거 이력을 쌓아두지 않고 "지금 확인 안 하면 손해인 것"만 보여준다.

### 3.4 최근 생성된 링크

5개까지만 표시, 전체는 `/projects/{id}/links`로 연결. 이 화면에는 링크 생성 폼을 직접 두지 않는다(v2가 "프로젝트는 서랍이 아니다" 원칙에 따라 생성은 `+ 링크 만들기` 클릭 시 드로어로 연다).

## 4. 링크 (`/projects/{id}/links`)

### 4.1 목적

프로젝트에 속한 모든 링크(캠페인 소속 여부 무관)를 찾고, 상태를 확인한다.

### 4.2 레이아웃

```text
링크                                          [+ 링크 만들기]
[전체 캠페인 ▾] [상태: 전체 ▾] [기간 ▾]  [🔍 코드·URL·external_id 검색]

☐  코드     목적지                    캠페인      상태      생성일       진입   이동
☐  aB3x9Q   example.com/summer...   여름 세일   사용 가능  08-10       120    93
☐  k2ZpQ1   example.com/landing     -           사용 가능  08-09       45     40
...
[선택 삭제] (1개 이상 선택 시에만 노출)
[더 보기]
```

### 4.3 링크 생성 (드로어)

`+ 링크 만들기` 클릭 시 우측 드로어가 열린다. 현재 `projects.html`의 `create-project-link-form`(원본 URL + 만료 옵션)을 그대로 재사용하되, 추가로 "캠페인에 포함" select(선택, 비우면 프로젝트 직속 링크)를 넣는다. 캠페인을 선택하면 해당 캠페인의 UTM 필드 입력이 드로어 안에서 함께 나타난다(현재 `campaigns.html`의 `campaign-utm-inputs` 로직 재사용).

생성 성공 시 드로어를 닫지 않고 v2 result panel 패턴(단축 URL + 복사, secret key 관련 안내는 프로젝트 링크는 secret key가 없으므로 생략)을 드로어 안에 인라인으로 보여준 뒤, 목록 최상단에 새 행을 추가한다.

### 4.4 링크 상세 드로어 (행 클릭)

```text
aB3x9Q                                          [설정] [닫기]
srrrg.link/aB3x9Q                        [열기] [복사]
→ example.com/summer-sale?utm_source=...

상태: 사용 가능       캠페인: 여름 세일        생성: 2026-08-01

최근 7일
진입 84   이동 71

UTM
utm_source   email
utm_medium   newsletter

[전체 통계 보기 →]
```

`설정` 클릭 시 같은 드로어 안에서 편집 모드로 전환(원본 URL, 만료 수정 — 현재 `management.html`의 settings-panel 폼 재사용). `전체 통계 보기`는 캠페인 통계 탭 또는 프로젝트 통계 화면의 해당 링크 필터로 이동한다.

## 5. 캠페인 목록 (`/projects/{id}/campaigns`)

```text
캠페인                                        [+ 캠페인 만들기]
[보관됨 보기 ☐]

이름          상태    링크 수   최근 7일 클릭   마지막 활동
여름 세일     활성    24        1,204          2시간 전
런칭 이벤트   활성    8         320            1일 전
봄맞이 프로모  보관됨   12        -              -
```

행 클릭 시 캠페인 상세(개요 탭)로 이동. 보관된 캠페인 행은 텍스트 색을 `--color-text-subtle`로 낮춰 "지금 활동 중이 아님"을 시각적으로 구분한다.

## 6. 캠페인 상세 (`/projects/{id}/campaigns/{cid}`)

### 6.1 공통 헤더

```text
캠페인 / 여름 세일                                    [보관하기]
[개요] [링크] [UTM 설정] [통계]
```

`보관하기`는 danger button이 아니라 secondary button으로 둔다 — soft delete이고 복구 가능하므로 프로젝트 삭제(하드 삭제)와 같은 위협도로 다루지 않는다(v2/v3 공통 톤 원칙).

### 6.2 개요 탭

```text
기본 목적지
example.com/summer-landing                    [변경]

UTM 템플릿: 이메일 캠페인용 (3개 필드)          [변경]

핵심 지표 (최근 7일)
진입 1,204   이동 980   이동률 81%

빠른 작업
[+ 링크 추가]  [CSV로 대량 추가]
```

현재 `campaigns.html`의 `default-destination-form`이 여기로 온다. 다만 편집은 인라인 폼이 아니라 `[변경]` 클릭 시에만 폼이 나타나는 방식으로 바꿔 평소에는 읽기 전용 요약만 보이게 한다(현재는 폼이 항상 펼쳐져 있어 "지금 설정값이 뭔지" 파악보다 "입력창이 있다"는 인상이 먼저 온다).

### 6.3 링크 탭

[4장](#4-링크-projectsidlinks) 컴포넌트에 `캠페인=이 캠페인` 필터가 고정된 뷰 + 아래 CSV 섹션 추가.

```text
[+ 링크 추가]  [CSV로 대량 추가 ▾]
  ├ CSV 양식 다운로드
  ├ CSV 업로드
  └ 현재 목록 CSV로 내보내기

(4장과 동일한 링크 테이블, 캠페인 컬럼은 이미 고정이므로 숨김)
```

CSV 관련 3개 액션(양식 다운로드/업로드/내보내기)은 현재처럼 3개의 독립 섹션으로 세로 나열하지 않고 하나의 드롭다운 메뉴로 묶는다 — 자주 쓰는 기능이 아니므로 화면 공간을 상시 차지할 필요가 없다.

CSV 업로드 진행 상태는 [03_visual_system.md](03_visual_system.md) 9장의 stepper를 사용, 업로드 후에도 이 탭에 머무르며 진행 상태를 보여준다(현재도 동일하게 페이지 이동 없이 상태만 갱신하는 방식이므로 이 부분은 로직 변경 없이 시각만 개선).

### 6.4 UTM 설정 탭

```text
사용 중인 템플릿: 이메일 캠페인용                [다른 템플릿 선택] [새 템플릿 만들기]

캠페인 기본값
utm_source    email
utm_medium    newsletter
utm_campaign  summer-sale
                                              [기본값 저장]

이 값은 링크에서 직접 지정하지 않은 필드에 적용되며, 변경 시 기존 링크에도 즉시 반영됩니다.
```

`다른 템플릿 선택`은 [UTM 템플릿 화면](#7-utm-템플릿-projectsidutm-templates)에서 만든 템플릿 목록을 드로어/모달로 보여주는 선택기를 연다. `새 템플릿 만들기`를 누르면 UTM 템플릿 화면으로 이동해 만들고 돌아오게 하거나, 간단한 이름 입력 정도는 인라인으로 허용하고 필드 편집은 UTM 템플릿 화면으로 유도한다(필드 편집이 여러 캠페인에 영향을 준다는 게 지금 문구에도 명시되어 있으므로, 그 영향 범위를 체감할 수 있는 "템플릿 전용 화면"에서 하는 게 맞다).

### 6.5 통계 탭

현재 캠페인 통계는 `statistics.html`로 별도 이동했는데, v3에서는 이 탭 안에서 프로젝트 통계 화면과 동일한 컴포넌트를 "이 캠페인으로 필터링된 상태"로 보여준다. 상세는 7장 참고.

## 7. UTM 템플릿 (`/projects/{id}/utm-templates`)

### 7.1 목적

프로젝트에서 재사용 가능한 UTM 스키마 자산을 만들고 관리한다.

### 7.2 레이아웃

```text
UTM 템플릿                                    [+ 템플릿 만들기]

┌─────────────────┬──────────────────────────────────┐
│ 이메일 캠페인용   │  이메일 캠페인용                    │
│ 3개 필드         │  사용 중인 캠페인: 여름 세일, 런칭 이벤트│
│ 2개 캠페인 사용중 │                                    │
│                 │  활성 필드 (최대 10개)                │
│ SNS 광고용       │  utm_source                    [삭제] │
│ 4개 필드         │  utm_medium                    [삭제] │
│ 1개 캠페인 사용중 │  utm_campaign                  [삭제] │
│                 │                                    │
│                 │  [필드 이름 (예: utm_content)  ] [추가] │
└─────────────────┴──────────────────────────────────┘
```

좌측은 템플릿 목록(선택형 리스트), 우측은 선택된 템플릿의 필드 편집 패널 — 현재 캠페인 화면에 있던 `template-picker` + `template-field-list`를 그대로 가져오되 캠페인 종속성을 없앤다.

### 7.3 필드 편집 경고

필드 추가/삭제는 "이 템플릿을 쓰는 모든 캠페인의 기존 링크와 통계에 즉시 반영된다"는 현재 문구(`template-fields-panel`의 help-text)를 유지한다. 다만 위치를 필드 목록 바로 위, 눈에 띄는 곳(warning-soft 배경 note)으로 격상한다 — 지금은 작은 `<p class="help-text">`라 놓치기 쉽다.

### 7.4 사용 중인 캠페인 표시

템플릿 상세에 "사용 중인 캠페인" 목록을 링크로 보여준다(현재는 이 정보가 화면 어디에도 없다 — 템플릿을 삭제/변경하기 전에 영향 범위를 알 수 없었다).

## 8. 통계 (`/projects/{id}/statistics`, 캠페인 통계 탭 공용)

### 8.1 목적

기존 `statistics.html`의 데이터 구성(핵심 지표 6종, 추이 차트, 결과/유입 도메인 분해, 링크 유입 상태, UTM별 이동, 캠페인 비교)은 유지한다. 바뀌는 것은 **필터 위계와 화면 내 정리**다.

### 8.2 레이아웃

```text
통계                                    [7일] [30일] [90일] [시작일] [종료일] [집계: 일▾] [적용]

전체 진입 4,301   전체 이동 3,502   사람 진입 4,010   사람 이동 3,344   미이동 799   봇 진입 291

접근 추이 (선 그래프, 접근/이동 두 계열)

┌ 결과 ─────────┐  ┌ 유입 도메인 ───────┐
│ ...           │  │ ...               │
└───────────────┘  └───────────────────┘

[링크별] [UTM별] [캠페인별]   ← 프로젝트 통계에서만 노출되는 하위 탭
```

### 8.3 프로젝트 vs 캠페인 통계의 차이

| | 프로젝트 통계 | 캠페인 통계 탭 |
|---|---|---|
| 범위 | 프로젝트 전체 | 해당 캠페인만 |
| 하위 탭 | 링크별 / UTM별 / 캠페인별(비교) 3개 | 링크별 / UTM별 2개 (캠페인별 비교는 의미 없으므로 제외) |
| 진입 경로 | 사이드바 `통계` | 캠페인 상세의 `통계` 탭 |

캠페인별 비교(`campaign-section`)는 프로젝트 통계에만 존재해야 한다. 현재 `statistics.html`에는 이 셋이 구분 없이 한 화면에 모두 있는데, 캠페인 상세로 진입했을 때는 "캠페인별 비교"가 문맥에 맞지 않으므로 숨긴다.

### 8.4 링크별 상태 표(`link-status-section`)

행이 많아질 수 있는 표이므로 [03_visual_system.md](03_visual_system.md) 4장 `.data-table` 표준을 적용하고, 행 클릭 시 4.4절 링크 상세 드로어를 연다(현재는 클릭 동작이 없어 보인다 — 표를 보는 것과 개별 링크를 관리하는 것이 단절되어 있었다).

## 9. 멤버 (`/projects/{id}/members`)

```text

                                        [권한 변경 ▾] [제거]

[이메일                          ] [권한: 편집 가능 ▾] [초대 보내기]

대기 중인 초대 (2)

```

- 멤버 목록과 초대 폼/대기 목록을 한 화면 안에서 위아래 섹션으로 분리한다(현재도 구조는 유사하나 `<details>` 안에 있어 기본적으로 접혀 있었다 — 독립 화면이 되면서 항상 펼쳐진 상태가 기본이 된다).
- 자기 자신의 행에는 `권한 변경`/`제거` 액션을 비활성화한다(소유자가 실수로 자신을 제거하는 것 방지 — 현재 구현 확인 필요, 명세로 명시).
- OWNER가 1명뿐인 프로젝트에서 그 OWNER의 권한 변경/제거는 막아야 한다(소유자 없는 프로젝트 방지). 이 규칙이 API에 없다면 별도로 백엔드 확인이 필요하다는 점을 QA 체크리스트에 남긴다.

## 11. 초대 수락 (`/invitations/{token}`)

현재 구현이 이미 상태(가능/불가능, 로그인 전/후, 수락 완료)를 잘 나누고 있다. v3에서 다듬을 점만 정리한다.

- `invitation-card`에 워크스페이스 셸을 적용하지 않는다 — 아직 로그인 전일 수도 있는 화면이므로 v2와 같은 셸 없는 카드형을 유지.
- 수락 완료 후 `프로젝트 열기` 버튼은 `/projects`가 아니라 방금 참여한 프로젝트로 바로 이동(`/projects/{id}`)하도록 링크를 구체화한다 — 현재는 `/projects`(스위처에서 다시 골라야 함)로 되어 있다.
