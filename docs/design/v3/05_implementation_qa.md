# srrrg UIUX v3 - 구현 및 QA

## 1. 현재 라우팅과의 차이

`HomeController`는 현재 화면 라우팅을 다음처럼 단순 매핑한다.

```text
GET /            → index
GET /manage      → management
GET /projects    → projects
GET /campaigns   → campaigns
GET /statistics  → statistics
GET /test/utm    → utm-test
```

v3는 `/projects`, `/campaigns`, `/statistics`를 프로젝트/캠페인 id를 포함한 경로로 세분화한다([02_information_architecture.md](02_information_architecture.md) 6장 표 참고). 이는 **JS 라우팅이 아니라 서버 컨트롤러에 신규 `@GetMapping`을 추가하는 작업**이며, srrrg의 다른 도메인들처럼 package-by-feature 구조를 따른다면 `HomeController`에 다 몰아넣기보다 `project/ProjectController`, `campaign/CampaignController` 같은 화면 전용 컨트롤러로 분리하는 편이 기존 구조와 일관적이다(현재 `HomeController`가 이미 비대해지고 있는 지점이기도 하다).

신규 경로는 모두 Thymeleaf에 최소한의 model 데이터(프로젝트 id, 초기 렌더용 이름 정도)만 넘기고, 실제 데이터는 기존처럼 프론트 JS가 `/api/web/...`를 호출해 채운다 — 이 부분은 지금 방식과 동일하게 유지한다.

## 2. CSS/JS 구조

### 2.1 신규 CSS 파일

```text
src/main/resources/static/css/srrrg/workspace-shell.css   ← 사이드바, 상단 바, 워크스페이스 스위처
src/main/resources/static/css/srrrg/data-table.css        ← 표준 data-table (여러 화면 공용)
src/main/resources/static/css/srrrg/drawer.css            ← 드로어 오버레이/패널
```

기존 `srrrg.css`(토큰 + 공통 컴포넌트)는 그대로 최상위 공통으로 유지하고, 위 3개 파일은 워크스페이스 셸에서만 추가로 로드한다. 비회원 홈(`index.html`)과 `/manage`는 이 3개 파일을 로드하지 않는다 — 셸이 없기 때문이다.

### 2.2 신규 JS

```text
src/main/resources/static/js/srrrg-workspace-shell.js   ← 사이드바 활성 상태, 워크스페이스 스위처, 상단 검색
src/main/resources/static/js/srrrg-drawer.js            ← 드로어 open/close, focus trap (공용 유틸)
```

기존 `srrrg-projects.js`, `srrrg-campaigns.js`, `srrrg-statistics.js`는 화면이 쪼개지는 만큼 로직도 함께 쪼개질 필요가 있다(예: `srrrg-campaigns.js` → 목록/상세/링크탭/UTM탭으로 분리). 이 리팩터링 범위는 크므로 4장의 단계별 마이그레이션을 따라 점진적으로 진행한다.

### 2.3 상태 관리 원칙

v2 4.3절의 JS 상태 관리 원칙(상태 이름 명확히 분리, DOM 조작 함수 분리)을 그대로 따르고, 추가로:

- 사이드바 활성 항목은 현재 URL 기준으로 계산하는 순수 함수로 분리한다(서버 렌더링 시점에 `aria-current`를 이미 넣어줄 수 있다면 그쪽이 더 안전 — JS로 나중에 켜는 것보다 깜빡임이 없다).
- 드로어는 한 번에 하나만 열린다는 전제로 단일 전역 상태(`activeDrawer`)로 관리한다.

## 3. 접근성 명세 (v2 상속 + 추가분)

v2 5장의 기본/Form/Modal/Dynamic Message 규칙은 전부 그대로 적용된다. 추가로 필요한 것:

### 3.1 사이드바 내비게이션

- `<nav aria-label="프로젝트 메뉴">`로 다른 내비게이션(상단 바, 브레드크럼)과 구분되는 landmark를 제공한다.
- 현재 화면은 `aria-current="page"`로 표시한다.
- 키보드로 사이드바 항목 간 이동은 일반 Tab 순서로 충분하다(화살표 키 커스텀 내비게이션은 불필요한 복잡도 — ARIA APG에서도 단순 링크 목록에는 권장하지 않는다).

### 3.2 드로어

v2 5.4절 Modal 규칙에서 다음만 다르게 적용한다.

- `aria-modal="false"` (배경 목록이 시각적으로 계속 보이므로)
- 배경 목록 컨테이너에 열려있는 동안 `inert` 속성 부여(지원 브라우저 우선, 미지원 시 `aria-hidden="true"` + 배경 클릭 방지로 폴백)
- 닫을 때 focus는 드로어를 연 트리거(테이블 행 또는 버튼)로 복귀

### 3.3 탭

캠페인 상세의 개요/링크/UTM 설정/통계 탭은 이미 `management.html`에 구현된 `console-tabs` 패턴(`role="tablist"`, `role="tab"`, `aria-selected`, `aria-controls`)을 그대로 재사용한다 — 새로 설계하지 않는다.

## 4. 마이그레이션 우선순위

한 번에 전체를 갈아엎지 않고 단계별로 진행한다. 각 단계는 독립적으로 배포 가능해야 한다.

### Phase 1 — 워크스페이스 셸 도입

- 사이드바 + 상단 바 fragment(`fragments/workspace-shell.html`) 신설
- 기존 `/projects`, `/campaigns`, `/statistics` 화면에 셸만 씌운다(내부 레이아웃은 아직 그대로)
- 완료 기준: 세 화면 모두 사이드바에서 서로 이동 가능, 기능 회귀 없음

### Phase 2 — 프로젝트 라우팅 분리 + 개요 화면 신설

- `/projects/{id}`, `/projects/{id}/members`, `/projects/{id}/settings` 경로 추가
- 개요 화면(3장) 신규 구현, 멤버/설정을 `<details>`에서 독립 화면으로 이동
- 완료 기준: `<details class="project-admin">` 제거, 기존 기능(초대, 서브도메인, 익명 링크 편입) 전부 동작

### Phase 3 — 링크 화면 통합

- `/projects/{id}/links` 신설, `.data-table` 표준 컴포넌트 도입
- 링크 상세 드로어 구현
- 완료 기준: 프로젝트 개요의 "최근 링크"와 이 화면이 같은 컴포넌트를 재사용

### Phase 4 — 캠페인 상세 탭 분리

- `/projects/{id}/campaigns/{cid}` 하위 4개 탭 라우팅
- CSV 관련 3개 액션을 드롭다운으로 통합
- 완료 기준: 캠페인 화면이 더 이상 단일 페이지에 8개 섹션을 나열하지 않음

### Phase 5 — UTM 템플릿 독립

- `/projects/{id}/utm-templates` 신설, 마스터-디테일 레이아웃
- 캠페인 상세의 UTM 설정 탭은 템플릿 선택기로 전환
- 완료 기준: 템플릿 생성/필드 편집을 캠페인 화면 밖에서도 할 수 있음

### Phase 6 — 통계 정리 + 접근성 QA

- 프로젝트 통계와 캠페인 통계 탭의 하위 탭 차이 반영(캠페인별 비교는 프로젝트에만)
- 링크별 상태 표에 드로어 연결
- 전체 워크스페이스 셸에 대해 6장 QA 체크리스트 통과

## 5. QA 체크리스트

### 5.1 워크스페이스 셸

- [ ] 사이드바의 현재 항목이 실제 화면과 일치한다.
- [ ] 워크스페이스 스위처로 다른 프로젝트 전환 시 사이드바 컨텍스트(어떤 프로젝트인지)가 즉시 갱신된다.
- [ ] VIEWER 권한 사용자에게 `멤버`, `설정` 메뉴가 보이지 않는다.
- [ ] Tablet 폭에서 사이드바가 아이콘만 남고, 라벨은 접근성 트리에 여전히 존재한다(`aria-label`).
- [ ] Mobile 폭에서 사이드바가 숨겨지고 햄버거로 열린다.

### 5.2 링크 화면 / 드로어

- [ ] 필터(캠페인/상태/기간)와 검색이 동시에 적용된다.
- [ ] 행 클릭으로 드로어가 열리고, 체크박스 클릭은 드로어를 열지 않는다.
- [ ] 드로어 열림 중 Escape로 닫히고 트리거로 focus가 복귀한다.
- [ ] 드로어 안에서 설정 변경 후 저장하면 뒤 목록의 해당 행도 갱신된다.
- [ ] 캠페인 소속 링크와 프로젝트 직속 링크가 같은 테이블에서 구분되어 보인다.

### 5.3 캠페인 상세

- [ ] 4개 탭 전환 시 URL이 바뀌고(딥링크 가능), 새로고침해도 같은 탭이 유지된다.
- [ ] 개요 탭의 기본 목적지/UTM 템플릿 요약이 실제 값과 일치하고, `변경` 클릭 시에만 폼이 나타난다.
- [ ] CSV 업로드 진행 상태가 처리 중 실시간(폴링)으로 갱신된다.
- [ ] 캠페인 보관(soft delete) 후 캠페인 목록에서 기본적으로 숨겨지고, `보관됨 보기`로 다시 보인다.

### 5.4 UTM 템플릿

- [ ] 템플릿 목록에서 "사용 중인 캠페인 수"가 실제와 일치한다.
- [ ] 필드 추가/삭제 전 경고 문구가 warning-soft 스타일로 눈에 띈다.
- [ ] 캠페인 상세에서 템플릿을 바꾸면 UTM 템플릿 화면의 "사용 중인 캠페인" 목록도 갱신된다.

### 5.5 멤버/설정

- [ ] 소유자가 1명뿐인 프로젝트에서 그 소유자의 권한 변경/제거 액션이 비활성화된다.
- [ ] 자기 자신의 멤버 행에서 제거 액션이 비활성화된다.
- [ ] 프로젝트 삭제는 danger zone 안에 있고, 확인 다이얼로그를 거친다.
- [ ] 서브도메인 변경/반납 후에도 기존 링크 주소가 그대로 동작한다는 안내 문구가 유지된다.

### 5.6 접근성 (v2 QA 체크리스트 6.5절 전체 + 아래 추가)

- [ ] 사이드바, 상단 바, 브레드크럼이 서로 다른 landmark(`nav`)로 스크린리더에서 구분된다.
- [ ] 탭 전환이 키보드만으로 가능하다(Tab으로 탭 리스트 진입 후 방향키 또는 Tab으로 각 탭 이동, Enter/Space로 활성화).
- [ ] 드로어가 열렸을 때 배경 목록이 스크린리더 탐색에서 제외된다(`inert` 또는 `aria-hidden`).

### 5.7 반응형

- [ ] 1024px 이상에서 사이드바 240px 고정, 콘텐츠 영역이 과도하게 넓어지지 않는다(최대 폭 유지).
- [ ] 768~1023px에서 사이드바가 64px로 축소되고 콘텐츠가 자연스럽게 넓어진다.
- [ ] 768px 미만에서 모든 신규 컴포넌트(data-table, 드로어)가 가로 스크롤 없이 동작한다(테이블은 `.data-table-wrap`의 `overflow-x: auto`로 감싸는 기존 패턴 유지).

## 6. 최종 방향 요약

v3의 핵심은 화면을 더 많이 만드는 것이 아니라 **이미 있는 기능을 우선순위에 맞게 재배치**하는 것이다.

- 프로젝트는 서랍에서 요약 화면으로 바뀐다.
- 캠페인은 나열식 페이지에서 탭이 있는 상세 페이지로 바뀐다.
- UTM 템플릿은 캠페인에 종속된 부속품에서 프로젝트 자산으로 독립한다.
- 링크는 캠페인 안에 갇히지 않고 프로젝트 전체에서 찾을 수 있다.
- 멤버·설정은 아코디언에서 벗어나 각자의 화면이 된다.

새 기능을 추가하는 문서가 아니라, **이미 만들어진 기능이 실제로 매일 쓰기 편한 위치에 있게 만드는** 재배치 작업이라는 게 v3의 핵심이다.
