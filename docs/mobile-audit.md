# 모바일 재검수

실제 모바일 viewport(320 / 360 / 390 / 430px)를 기준으로 레이아웃 깨짐과 불필요한 문구를 점검했다.

## 검증 도구와 그 한계 (먼저 밝힘)

| 도구 | 로그인 | 실제 모바일 viewport | 캡처 신뢰도 |
|---|---|---|---|
| Chrome | ✅ | ❌ `resize_window` 거부 | ✅ 데스크톱 폭에서 정확 |
| 인앱 브라우저 | ❌ | ✅ 320/360/390/430 적용됨 | ⚠️ 이미지 축척이 실측과 불일치 |

Chrome 리사이즈가 막힌 이유를 확인했다 — 창이 `screenX: -967` 로 화면 밖에 있어
`resize_window` 가 "Bounds must be at least 50% within visible screen space" 로 거부한다.
크기 문제가 아니라 위치 문제이고 이 도구는 위치를 옮기지 못한다.

인앱 브라우저는 viewport 에뮬레이션이 실제로 동작하지만(`innerWidth` 가 320/360/390/430 으로 바뀜)
세션이 없어 로그인 화면 이후로 못 들어간다. 캡처 이미지는 축척이 어긋나
광학 판단에는 못 쓰고, **실측값(레이아웃 계산 결과)은 정확하다.**

그래서 이번 검수는 이렇게 나눴다.

- **비회원 화면**(홈·로그인·오류·`/manage` 게이트): 인앱 브라우저에서 4폭 실측
- **로그인 화면**: Chrome 에서 코드 + 실측 + 강제 `@media` 규칙으로 구조 검증
- **로그인 화면의 4폭 실측**: 미완 — 아래 "남은 작업" 참조

## 1. 프로젝트 설정: 라벨·체크박스·상태가 세 줄로 찢어짐 (수정)

**원인은 모바일이 아니라 마크업이었다.**

```html
<label class="field">
  <span class="field-label">신규 링크에 사용</span>
  <input id="project-subdomain-enabled" type="checkbox"> 활성화
</label>
```

`.field` 는 `display: grid; gap: 8px` 다. 이 안에 세 개가 들어 있었다 —
`<span>` 라벨, `<input>` 체크박스, 그리고 익명 그리드 아이템이 되는 맨 텍스트 `활성화`.
grid 는 이 셋을 각각 **자기 행**에 놓는다. 즉 폭과 무관하게 항상 3행으로 찢어져 있었고,
데스크톱에서는 열이 넓어 덜 눈에 띈 것뿐이다.

**문구도 같은 것을 세 번 말했다** — "신규 링크에 사용"(라벨) + "활성화"(상태) + 체크박스 자체.
체크된 상태가 곧 활성화이므로 별도 상태 텍스트가 필요 없다.

**수정** 재사용 가능한 `.checkbox-row` 컴포넌트를 만들고 한 문장으로 합쳤다.

```html
<label class="checkbox-row" for="project-subdomain-enabled">
  <input id="project-subdomain-enabled" type="checkbox" aria-describedby="subdomain-availability">
  <span>새 링크를 이 서브도메인으로 발급</span>
</label>
```

```css
.checkbox-row {
  display: flex; gap: var(--space-2); align-items: center;
  min-height: var(--touch-min);   /* 44px */
  font-size: var(--text-sm); cursor: pointer;
}
.checkbox-row input[type="checkbox"] { width: 20px; height: 20px; margin: 0; flex: 0 0 auto; }
.checkbox-row:has(input:disabled) { color: var(--color-text-subtle); cursor: not-allowed; }
```

**검증 (Chrome 실측)**

| 항목 | 값 |
|---|---|
| `display` | `flex` |
| 체크박스 | 20×20, top 685 |
| 텍스트 | top 684 → **같은 행** (`sameRow: true`) |
| 클릭 영역 높이 | **44px** |
| `label` 이 `input` 을 감쌈 | ✅ 글자를 눌러도 토글 |
| 비활성 상태 | `:has(input:disabled)` 로 색만 낮춤, 의미 유지 |

`.field` 안에 체크박스를 넣은 다른 곳이 없는지 전수 확인했다 — 이 한 곳뿐이었다.
캠페인 링크 목록의 전체 선택 체크박스는 이미 flex 였고, 일관성을 위해 같은 클래스를 붙여
터치 영역을 44px 로 맞췄다.

**부수 정리** 컨트롤 이름이 바뀌었으므로 JS 안내 문구도 맞췄다.
"서브도메인을 먼저 선점하면 활성화와 반납을 쓸 수 있습니다" → "먼저 서브도메인을 선점하세요",
"활성화하면 신규 링크에 사용됩니다" → "체크하면 새 링크에 적용됩니다".
화면에 없는 이름("활성화")을 안내가 계속 부르고 있으면 안 된다.

## 2. 캠페인 링크 목록: 카드 8행 → 6행 + 내부 여백 (수정)

가로 스크롤은 이전 작업에서 이미 카드형 전환(`.stacking-table`)으로 없앴다.
이번에는 카드 자체의 밀도를 봤다.

**문제**
열이 8개라 카드 하나가 8행이 됐다. 그리고 카드가 테두리 있는 래퍼 안에 놓이는데
행에 좌우 여백이 없어(`padding: var(--space-3) 0`) 값이 테두리에 붙었다.

**수정**
- 행 여백 `12px 0` → **`12px`** (사방)
- 모바일 카드에서 `생성일` 과 `우리 쪽 식별자` 두 행을 감춤

목록에서 하는 일은 "내 링크를 훑고 하나를 집어 가는 것" 이다.
그 판단에 쓰는 값은 이름·코드·복사·UTM·목적지이고, 생성일과 내부 식별자는
링크 상세 화면에서 그대로 볼 수 있어 정보가 사라지지 않는다.
- 목적지 셀에 `overflow-wrap: anywhere` — 긴 URL 이 카드 폭을 넘기지 않게

**검증 (강제 ≤720px 규칙, Chrome 실측)**

| 항목 | 값 |
|---|---|
| 카드 모드 전환 | `thead: none` ✅ |
| 보이는 행 | 선택 · 이름 · 단축 코드 · 복사 · UTM · 목적지 (**6**) |
| 감춘 행 | 우리 쪽 식별자 · 생성일 (**2**) |
| 행 여백 | `12px` |
| 링크 카드 1개 높이 | 224px |
| 래퍼 가로 넘침 | 없음 |
| 전체 선택 체크박스 높이 | 44px |

핵심 행동은 모두 접근 가능하다 — 코드(→ 링크 상세), 복사, UTM 팝오버, 선택 후 삭제.
삭제는 행별 버튼이 아니라 체크박스 + 툴바의 "선택 삭제" 이므로 체크박스 터치 영역이 중요했고
그것을 44px 로 올렸다.

## 3. 문구 정리 (7곳)

원칙은 세 가지로 잡았다.
**(a)** 화면이 이미 보여 주는 것을 문장으로 되풀이하지 않는다.
**(b)** 사용자가 그 문장으로 할 행동이 없으면 지운다.
**(c)** 제품 용어·API 계약은 영어를 유지한다.

| 위치 | 전 | 후 | 이유 |
|---|---|---|---|
| `projects.html` 워크스페이스 설명 | "팀과 함께 쓰는 단축 URL을 프로젝트 도메인에서 만들고 관리하세요." | **삭제** | 이미 프로젝트 안에서 작업하는 사람에게 제품을 소개하는 문장. 얻는 행동이 없고 모바일에서 한 줄을 차지 |
| `projects.html` 빈 상태 | "프로젝트는 팀이 함께 쓰는 작업 공간입니다. 만들고 나면 프로젝트 도메인으로 단축링크를 발행하고, 캠페인과 UTM 템플릿으로 채널별 성과를 나눠 볼 수 있습니다." (90자) | "팀이 함께 쓰는 작업 공간입니다. 만들면 전용 도메인으로 링크를 만들고 캠페인별 성과를 볼 수 있습니다." | 빈 상태에서 설명은 제 일을 하지만 세 가지를 한 호흡에 말했다. 버튼을 누를지 정하는 데 필요한 둘만 남김 |
| `project-utm-templates.html` 화면 설명 | "…관리합니다. 캠페인에서는 여기서 만든 템플릿을 선택합니다." | "캠페인 링크에 붙일 UTM 필드 구성을 관리합니다." | 둘째 문장을 바로 아래 빈 상태가 같은 말로 반복 |
| `project-utm-templates.html` 필드 도움말 | 3문장 (77자) | "표준 이름을 쓰면 GA 같은 분석 도구가 그대로 인식합니다." | `datalist` 가 목록을 이미 보여주므로 "고르거나 입력하세요" 는 컴포넌트 사용법 설명. 허용 문자는 `pattern` 이 검증해 브라우저가 알림 |
| `campaigns.html` 식별자 도움말 | "주문번호처럼 내부에서 쓰는 값을 넣어 성과를 구분합니다. …API와 CSV에서는 `external_id` 입니다." | "주문번호 같은 내부 식별자. 이메일·이름·전화번호는 넣지 마세요. API·CSV에서는 `external_id`." | 세 사실(용도·금지·API 이름)을 모두 유지하고 서술을 줄임. 도움말은 명사형이 자연스럽다 |
| `project-members.html` 초대 안내 | "이메일로 초대 링크를 보냅니다. 링크를 열어 로그인한 계정이 참여하므로 링크가 전달되지 않도록 안내하세요." | "초대 링크를 연 계정이 그대로 참여합니다. 링크를 다른 사람에게 전달하지 마세요." | 앞 문장은 바로 아래 폼(초대할 이메일 + 초대 보내기)이 이미 보여 준다. 남길 것은 전달 위험 |
| `project-settings.html` 서브도메인 | "선점할 서브도메인" / "선점하기" / "서브도메인 반납" / "활성화 여부와 관계없이 서브도메인은 선점됩니다. 변경·반납해도 기존 링크 주소는 유지됩니다." | "서브도메인" / "선점" / "반납" / "바꾸거나 반납해도 이미 만든 링크 주소는 그대로 동작합니다." | 버튼이 동작을 말하므로 라벨이 되풀이할 필요 없음. 섹션 제목이 "서브도메인" 이라 버튼에서 반복 제거. 앞 문장은 내부 동작 설명이라 사용자가 할 행동이 없음 |

**영어를 유지한 것** `secret key`, `external_id`, `UTM`, `API key`, `code`, `OpenAPI JSON`.
전부 제품 용어이거나 API·CSV 계약에 그대로 등장하는 이름이라 한국어로 옮기면
문서·응답과 대조가 끊긴다. 반대로 상태명(`사용 가능`, `만료 없음`)은 최종 사용자가 읽는 값이라
한국어를 유지했다.

## 4. 비회원 화면 4폭 실측 (인앱 브라우저)

**홈** — 320 / 360 / 390 / 430px 전부

| 폭 | 가로 넘침 | 밖으로 밀린 요소 | 잘린 텍스트 | 컨트롤 겹침 | 문서 높이 |
|---|---|---|---|---|---|
| 320 | 없음 | 0 | 0 | 0 | 1240px |
| 360 | 없음 | 0 | 0 | 0 | 1168px |
| 390 | 없음 | 0 | 0 | 0 | 1151px |
| 430 | 없음 | 0 | 0 | 0 | 1108px |

**로그인** 320px — 가로 넘침 없음, 밖으로 밀린 요소 0.

24px 미만으로 잡힌 요소는 전부 문장 안 인라인 링크(브랜드 워드마크,
"링크 관리 열기", "API 문서 보기", "OpenAPI JSON")로 WCAG 2.5.8 의 인라인 예외에 해당한다.
블록 컨트롤(버튼·입력·선택)에는 24px 미만이 없다.

첫 화면에서 가장 먼저 읽히는 정보와 다음 행동:
- **홈** → "긴 링크를 짧고 안전하게" 다음 바로 URL 입력창. 다음 행동은 URL 붙여넣기.
  만료 칩 6개는 320px 에서 "만료 설정 / 없음" 한 줄 디스클로저로 접힌다(기존 반응형 설계).
- **로그인** → "srrrg에 로그인" + OAuth 3개. 다음 행동은 계정 선택.

## 남은 작업 (완료로 보고하지 않는 이유)

요청하신 완료 조건 중 **로그인 화면의 320/360/390/430 실측·캡처**를 아직 못 했다.
프로젝트 개요·프로젝트 설정·캠페인 목록·캠페인 링크 목록·통계·UTM 템플릿·온보딩이 해당한다.

- Chrome: 세션은 있으나 창이 화면 밖에 있어 리사이즈가 거부됨
- 인앱 브라우저: 리사이즈는 되지만 세션이 없어 `/login` 으로 리다이렉트됨

자격증명을 직접 입력하지 않는다는 원칙 때문에 인앱 브라우저 로그인은 사용자가 해 주어야 한다.
그 세션이 준비되면 위 7개 화면을 4폭에서 캡처·실측해 이 문서에 이어 기록한다.

현재까지의 수정은 코드 원인 분석 + Chrome 실측 + 강제 `@media` 규칙으로 검증했고,
`.checkbox-row` 는 flex 한 줄 구조라 폭에 따라 찢어질 수 없는 형태다.
다만 좁은 폭에서의 줄바꿈·광학 균형은 실측으로 확인해야 한다.
