# 단계별 구현 실행 프롬프트

아래 프롬프트를 Codex task에 그대로 붙여 넣어 사용한다. 모든 단계는 `Sol / 중간`으로 실행하고, 한 번에 한 단계만 구현하며, 미확정 사항 확인 전에는 코드를 수정하지 않는다.

```text
srrrg의 로그인·프로젝트·캠페인 확장 계획을 단계별로 구현해줘.

기준 문서:
- docs/conventions.md
- docs/architecture/project_campaign_personalized_links.md
- docs/implement/01_create_link_api.md
- docs/implement/02_manage_link_api.md
- docs/implement/03_authenticated_projects_campaigns.md
- docs/implement/05_implementation_checklist.md

중요: 전체 계획을 한 번에 구현하지 마라. 이번 task에서는 아직 완료되지 않은 다음 단계 하나만 다룬다.

OAuth 이메일 정책:
- OAuth 최초 가입과 로그인에서 이메일을 필수로 요구하지 않는다.
- 공급자가 이메일을 제공하지 않더라도 `(provider, provider_user_id)`로 사용자를 식별해 가입과 로그인을 허용한다.
- 제공된 이메일은 저장할 수 있지만, 이메일이 없다는 이유로 인증을 거부하지 않는다.
- 이메일이 필요한 기능을 도입할 때 프로필 수정 화면에서 입력·검증받는다. 그전에는 해당 화면과 API를 미리 만들지 않는다.
- 기존 이메일 기반 계정 연결의 보안 원칙은 유지하되, 이메일이 없는 계정을 자동 병합하지 않는다.
- 현재 구현이나 문서가 이 정책과 다르면 다음 단계보다 이 정책 수정을 먼저 다루고, 이메일 입력·검증 시점처럼 확정되지 않은 사항은 구현 전에 질문한다.

먼저 읽기 전용으로 다음 작업만 수행해라.
1. git status와 현재 코드를 확인한다.
2. 구현 체크리스트의 체크 상태를 현재 코드와 테스트로 검증한다.
3. 체크리스트와 코드가 다르면 임의로 고치지 말고 차이를 보고한다.
4. 구현 명세서의 완료 조건과 체크리스트를 기준으로 다음 미완료 단계 하나를 판정한다.
5. 판정이 애매하면 추측하지 말고 나에게 질문한다.

다음 단계를 정하면 모델 설정을 확인하거나 변경을 요청하지 말고 다음 순서로 진행해라.

1. 기준 문서와 해당 단계에 관련된 docs를 처음부터 끝까지 다시 읽는다.
2. 현재 코드, 테스트와 모든 Flyway migration을 확인한다.
3. 문서와 코드의 충돌 및 구현 전에 필요한 미확정 정책을 모두 찾는다.
4. docs/implement/03_authenticated_projects_campaigns.md의 질문 게이트에 따라 질문을 한 번에 정리한다.
5. 질문이 하나라도 있으면 코드를 수정하지 말고 내 답을 기다린다.
6. 질문이 없더라도 구현 범위와 제외 범위를 짧게 설명하고 구현 시작 여부를 한 번 확인받는다.
7. 내가 구현을 승인한 뒤에만 현재 단계 하나를 구현한다.

구현 규칙:
- 기존 익명 링크 생성·관리 API, X-Srrrg-Secret-Key, management 화면과 리다이렉트를 보존한다.
- 이번 개발에서는 프로젝트별 플랫폼 서브도메인만 구현하고, 커스텀 도메인·CNAME 검증·도메인별 인증서·동적 Ingress는 구현하지 않는다.
- 기존 Flyway migration을 수정하지 않는다.
- 사용자 변경사항을 덮어쓰거나 되돌리지 않는다.
- 단일 Gradle 모듈과 기능별 패키지 경계를 유지한다.
- 구현체가 하나인 service와 repository에 불필요한 interface를 만들지 않는다.
- 후속 단계용 테이블, API, 추상화와 인프라를 미리 만들지 않는다.
- 보안, 데이터 손실 방지, 입력 검증과 접근성은 단순화를 이유로 생략하지 않는다.
- 명세에 없는 중요한 결정을 가장 그럴듯한 값으로 임의 처리하지 말고 반드시 질문한다.
- 커밋은 만들지 않는다.

구현 후:
1. 해당 단계 테스트를 실행한다.
2. 기존 익명 링크 생성·조회·수정·삭제·리다이렉트 회귀 테스트를 실행한다.
3. 코드와 테스트로 검증된 구현 항목만 docs/implement/05_implementation_checklist.md에서 `[x]`로 갱신한다.
4. 일부만 구현됐으면 해당 하위 항목만 체크하고 단계 완료는 체크하지 않는다.
5. 실패 원인을 해결하지 못하면 완료라고 보고하지 않는다.
6. 변경 파일, 체크리스트 갱신, 검증 결과, 남은 위험과 다음 단계를 간결하게 보고한다.
7. 다음 단계 구현은 자동으로 시작하지 않는다.
```

단계를 자동 판정시키고 싶지 않으면 첫 문장의 다음 줄에 `이번 실행 단계: N단계`를 추가한다.
