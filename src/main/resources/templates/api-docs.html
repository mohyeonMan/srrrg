DEVELOPER API

API 문서

프로젝트 링크, 캠페인, UTM 템플릿과 통계를 외부 시스템에서 관리합니다.

OpenAPI JSON
시작하기 인증과 권한 공통 규칙 엔드포인트 오류 요청 한도

시작하기

  1. 키 발급프로젝트의 API 탭에서 OWNER가 필요한 scope를 선택해 키를 만듭니다.
  2. 키 보관전체 키는 발급 직후 한 번만 표시됩니다. 서버의 secret 저장소에 보관하세요.
  3. 요청 전송Authorization: Bearer srrrg_pk_... 헤더를 모든 /api/v1/** 요청에 넣습니다.
API 키 관리 기본 URL https://srrrg.link

첫 요청

curl -H "Authorization: Bearer srrrg_pk_..." \
  "https://srrrg.link/api/v1/projects/{projectId}/links?limit=20"

인증과 권한

API 키는 하나의 프로젝트에 속합니다. URL의 projectId와 키의 프로젝트가 다르면 요청이 거부됩니다.

scope허용 작업
links:read프로젝트·캠페인 링크 목록, CSV 내보내기
links:write링크 생성, JSON batch, CSV 가져오기
campaigns:read캠페인, UTM 템플릿·기본값, 가져오기 상태 조회
campaigns:write캠페인과 UTM 템플릿·필드·기본값 변경
stats:read프로젝트·캠페인·링크 통계 조회
익명 링크 API는 인증 방식이 다릅니다. POST /api/links는 키 없이 호출하고, 이후 조회·수정·삭제·통계에는 발급 당시의 X-Srrrg-Secret-Key를 사용합니다.

공통 규칙

Idempotency-Key
단일 링크 생성에는 권장하며, JSON batch와 CSV 업로드에는 필수입니다. 같은 작업의 재시도에는 같은 값을 사용하세요.
페이지네이션
목록은 cursor와 limit를 사용합니다. 응답의 다음 cursor를 그대로 전달하세요.
날짜와 시각
날짜는 YYYY-MM-DD, 시각은 ISO 8601 UTC 형식(예: 2026-08-16T03:00:00Z)을 사용합니다.
개인정보
externalId와 UTM 값에 이메일, 이름, 전화번호 같은 개인정보를 넣지 마세요.

오류

/api/v1/**의 인증·권한·요청 제한 오류는 application/problem+json이며 응답 헤더에 X-Request-Id가 포함됩니다.

{
  "title": "Forbidden",
  "status": 403,
  "detail": "필요한 API key scope가 없습니다.",
  "code": "INSUFFICIENT_SCOPE",
  "requestId": "..."
}

익명 링크 API와 일부 통계 도메인 오류는 현재 {"code":"...","message":"..."} 형식입니다. 클라이언트는 HTTP 상태를 먼저 판단하고 code를 분기 기준으로 사용하세요.
